## 1. Список систем

| # | Система | Тип системы | Функциональность | Тип функциональности | Комментарий / что нужно доработать |
|---|---------|-------------|-----------------|---------------------|-------------------------------------|
| С-1 | **ИС «Алмазы»** | Существующая | Учёт алмазов, присвоение идентификаторов, ведомости | Существующая | Отсутствует статусная модель для онлайн-процесса («в офисе» → «отправлен в лабораторию» → «оцифрован» → «выставлен на аукцион» → «продан»). Нет API для интеграций с ИС «Лаборатория» и ИС «Логистика». Нет инструмента отбора алмазов для цифрового аукциона. |
| С-2 | **ИС «Алмазы»** | Существующая | Отбор алмазов для цифрового аукциона и формирование задания на оцифровку | **Новая** | Новая функция в рамках существующей системы. В Фазе 1 — формирование Excel-ведомости вручную. В Фазе 2 — автоматическая отправка задания через API (И-1). |
| С-3а | **ИС «Аукцион»** | Существующая | Проведение офлайн-аукционов: логика торгов, управление участниками | Существующая | Система работает только в офлайн-режиме. Отсутствует поддержка онлайн-торгов, публикации цифровых описаний алмазов и личного кабинета покупателя. |
| С-3б | **ИС «Аукцион»** | Существующая | Публикация данных о лотах для покупателей, онлайн-торги, дашборд статуса подготовки | **Новая** | Существенное расширение. В Фазе 1 — использование существующей ИС с минимальной адаптацией под онлайн-формат (без полных доработок). В Фазе 2 — полная реализация: онлайн-витрина, личный кабинет, приём API-данных от ИС «Лаборатория». |
| С-4а | **ИС «Логистика»** | Существующая | Управление перевозками алмазов внутри страны и за рубеж, актирование | Существующая | Отсутствует поддержка нового маршрута «офис → лаборатория → офис». Нет механизма автоматического уведомления ИС «Алмазы» о статусе перевозки. В Фазе 1 — заявка через Excel-шаблон вручную. |
| С-4б | **ИС «Логистика»** | Существующая | Управление маршрутом «офис → лаборатория → офис», трекинг статуса алмазов в пути | **Новая** | Новый тип маршрута с цепочкой хранения. В Фазе 2 — автоматическая интеграция с ИС «Алмазы» для обновления статусов алмазов (И-4). |
| С-5а | **ИС «Бухгалтерия»** | Существующая | Учёт контрактов, актирование и оплата услуг перевозчиков | Существующая | Отсутствует возможность ведения контракта с лабораторией и автоматического приёма актов от ИС «Лаборатория». В Фазе 1 — ручной ввод на основании полученных бумажных актов. |
| С-5б | **ИС «Бухгалтерия»** | Существующая | Актирование услуг лаборатории, приём платёжных данных от Платёжного модуля | **Новая** | Новые функции в рамках существующей системы. В Фазе 2 — автоматический приём актов через API (И-3) и данных о сделке от Платёжного модуля (И-8). |
| С-6 | **ИС «Лаборатория»** | **Новая** | Приём заданий, проведение инструментального анализа алмазов (3D-сканирование, спектральный анализ, UV-флуоресценция), формирование стандартизированного цифрового описания, передача описаний в ИС «Аукцион», формирование актов для ИС «Бухгалтерия» | **Новая** | Полностью новая система у внешнего подрядчика. В Фазе 1 — передача данных через Excel/ZIP по защищённому каналу (вручную). В Фазе 2 — API-интеграция по зафиксированному контракту (И-1, И-2, И-3). Форматы данных (JSON, TIFF/JPEG2000, STL/OBJ) должны быть согласованы до начала разработки. |
| С-7 | **Облачное хранилище (S3-совместимое)** | **Новая** | Публикация медиа-данных о лотах (изображения, 3D-модели) для доступа покупателей в Фазе 1 | **Новая** | Временная система, используемая только в Фазе 1. В Фазе 2 — заменяется on-premise объектным хранилищем. Требует заключения контракта с облачным провайдером (SLA ≥ 99,9%, экспорт данных без вендорлока). |
| С-8 | **KYC-модуль** | **Новая** | Цифровой онбординг покупателей: загрузка документов, верификация, электронное подписание NDA, хранение KYC-документов, передача статуса в ИС «Аукцион» | **Новая** | Новый изолированный компонент. В Фазе 1 — ручной процесс: email + PDF + проверка compliance-офицером. В Фазе 2 — автоматизированный API-based онбординг с liveness-check и сверкой с санкционными списками. |
| С-9 | **Платёжный модуль** | **Новая** | Выставление счёта победителю торгов, приём оплаты (SWIFT/SEPA/РФ), отслеживание статуса платежа, разблокировка логистической цепочки при подтверждении оплаты | **Новая** | Новый компонент. В Фазе 1 — оплата вне платформы (банковский перевод), статус фиксируется оператором вручную в ИС «Бухгалтерия». В Фазе 2 — отдельный сервис с API-интеграциями (И-6, И-7, И-8). |
| С-10 | **ESB / API Gateway** | **Новая** | Централизованная маршрутизация сообщений, мониторинг интеграций, управление API-ключами и сертификатами, повторная доставка при сбоях | **Новая** | Только целевое решение (Фаза 2). В Фазе 1 — не требуется (прямые ручные обмены). В Фазе 2 — выбор между open-source (Apache Camel, Kong) и коммерческим решением. |
| С-11 | **Excel-реестры (шаблоны)** | **Новая** | Ведомость на оцифровку для лаборатории (П-1), получение данных от лаборатории (П-2), заявка на логистику (П-4) | **Новая** | Временные инструменты только Фазы 1. Форматы шаблонов должны быть утверждены до первой перевозки. В Фазе 2 — выводятся из эксплуатации и заменяются API-интеграциями. |

## 2. Список интеграций

### 2.1 Существующие интеграции (сохраняются)

| # | Интеграция | Тип | Реализация | Передаваемые данные | Тип данных | Комментарий |
|---|-----------|-----|-----------|---------------------|-----------|-------------|
| ЭИ-1 | ИС «Алмазы» → ИС «Логистика» | Существующая | Автоматическая (протокол уточнить) | Заявки на перевозку алмазов | **Существующие** | Сохраняется без изменений. В Фазе 2 расширяется поддержкой нового маршрута «офис → лаборатория → офис». |
| ЭИ-2 | ИС «Логистика» → ИС «Бухгалтерия» | Существующая | Автоматическая (протокол уточнить) | Акты выполненных перевозок, данные для оплаты перевозчиков | **Существующие** | Сохраняется без изменений. |

### 2.2 Новые интеграции Фазы 2 (автоматические)

| # | Интеграция | Тип | Реализация | Передаваемые данные | Тип данных | Комментарий |
|---|-----------|-----|-----------|---------------------|-----------|-------------|
| И-1 | ИС «Алмазы» → ИС «Лаборатория» | **Новая** | Автоматическая / REST API + mTLS | Задание на оцифровку: список алмазов, уникальные идентификаторы, сроки выполнения | **Новые** | Фаза 2. API-контракт должен быть зафиксирован до начала разработки. В Фазе 1 — заменяется Excel-ведомостью (П-1). |
| И-2 | ИС «Лаборатория» → ИС «Аукцион» | **Новая** | Автоматическая / REST API (JSON + бинарные файлы) | Цифровое описание алмаза: изображения высокого разрешения (TIFF/JPEG2000), 3D-модель (STL/OBJ), метрики качества, данные о флуоресценции и включениях | **Новые** | Фаза 2. Ключевая интеграция для публикации данных лотов. В Фазе 1 — заменяется ручной загрузкой файлов в облако (П-2, П-3). |
| И-3 | ИС «Лаборатория» → ИС «Бухгалтерия» | **Новая** | Автоматическая / REST API или EDI | Акты выполненных работ по оцифровке: перечень алмазов, объём работ, стоимость, реквизиты | **Новые** | Фаза 2. В Фазе 1 — заменяется ручным вводом на основе бумажных актов (П-5). |
| И-4 | ИС «Логистика» → ИС «Алмазы» | **Новая** | Автоматическая / Event (webhook) | Уведомления об изменении статуса перевозки: алмазы отправлены / прибыли в лабораторию / возвращены в офис | **Новые** | Фаза 2. Обеспечивает автоматическое обновление статусной модели лота в ИС «Алмазы». В Фазе 1 — ручное обновление статусов. |
| И-5 | KYC-модуль → ИС «Аукцион» | **Новая** | Автоматическая / REST API + OAuth 2.0 | Статус верификации покупателя: «верифицирован» / «не верифицирован» / «на проверке». ИС«Аукцион» блокирует доступ к торгам до получения статуса «верифицирован» | **Новые** | Фаза 2. В Фазе 1 — статус передаётся вручную compliance-офицером. |
| И-6 | ИС «Аукцион» → Платёжный модуль | **Новая** | Автоматическая / REST API (event-driven) | Данные результата торгов: ID победителя, ID лота, итоговая цена, валюта. Инициирует выставление счёта | **Новые** | Фаза 2. Однократное событие при закрытии лота. В Фазе 1 — оператор вручную фиксирует победителя и направляет счёт. |
| И-7 | Платёжный модуль → ИС «Аукцион» | **Новая** | Автоматическая / REST API (webhook) | Статус оплаты: «ожидается» / «подтверждена» / «просрочена». При статусе «подтверждена» — разблокировка логистической цепочки | **Новые** | Фаза 2. В Фазе 1 — оператор вручную меняет статус в ИС после подтверждения банковского перевода. |
| И-8 | Платёжный модуль → ИС «Бухгалтерия» | **Новая** | Автоматическая / REST API (JSON, идемпотентная) | Реквизиты завершённой сделки: ID аукциона, ID лота, ID покупателя, сумма, валюта, дата платежа, банковские реквизиты. Используется для формирования договора купли-продажи, акта и финансовой отчётности | **Новые** | Фаза 2. Требует идемпотентности — повторная доставка при сбоях не должна создавать дублирующие записи в ИС «Бухгалтерия». |

### 2.3 Промежуточные интеграции Фазы 1 (ручные)

| # | Интеграция | Тип | Реализация | Передаваемые данные | Тип данных | Комментарий |
|---|-----------|-----|-----------|---------------------|-----------|-------------|
| П-1 | ИС «Алмазы» → ИС «Лаборатория» | **Новая (временная)** | Ручная / Excel-ведомость по утверждённому шаблону + защищённая электронная почта | Список алмазов, их идентификаторы, требования к оцифровке, сроки | **Новые** | Заменяет И-1 в Фазе 1. Выводится из эксплуатации в Фазе 2 при вводе автоматической интеграции. |
| П-2 | ИС «Лаборатория» → Облачное хранилище | **Новая (временная)** | Ручная / Excel или ZIP-архив, защищённый канал (VPN / SFTP) | Цифровые описания алмазов: изображения, 3D-модели, метрики качества | **Новые** | Заменяет И-2 в Фазе 1. Сотрудник вручную загружает полученные файлы в облако. |
| П-3 | Облачное хранилище → ИС «Аукцион» / Покупатели | **Новая (временная)** | Ручная / ссылки на файлы в облаке, публикуемые оператором | Ссылки на медиа-данные лотов для просмотра покупателями | **Новые** | Временное решение для Фазы 1. Заменяется прямой интеграцией ИС «Лаборатория» → ИС «Аукцион» в Фазе 2. |
| П-4 | ИС «Алмазы» → ИС «Логистика» (новый маршрут) | **Новая (временная)** | Ручная / Excel-заявка по утверждённому шаблону | Заявка на перевозку по маршруту «офис → лаборатория → офис»: список алмазов, адреса, сроки, страховая стоимость | **Новые** | Дополняет существующую интеграцию ЭИ-1 для нового типа маршрута. В Фазе 2 — автоматизируется в рамках расширения ЭИ-1. |
| П-5 | ИС «Лаборатория» → ИС «Бухгалтерия» | **Новая (временная)** | Ручная / ручной ввод оператором на основании полученных бумажных актов | Данные актов: перечень оцифрованных алмазов, стоимость услуг, реквизиты лаборатории | **Новые** | Заменяет И-3 в Фазе 1. Риск ошибок при ручном вводе. Выводится из эксплуатации в Фазе 2. |
